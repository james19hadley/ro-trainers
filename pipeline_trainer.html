📖 RISC-V Pipeline & Hazard Handbuch (Klausur-Spickzettel)

1. Die 5 Stufen der RISC-V Pipeline

IF (Instruction Fetch): Befehl wird per PC aus dem Speicher geholt, PC += 4.
ID (Instruction Decode): Befehl dekodieren, Registerwerte aus Register File lesen.
EX (Execute): ALU-Berechnungen (Addition, Verschiebung, Adressberechnung, Branch-Bedingung).
MEM (Memory): Daten-Speicherzugriff (lw liest aus RAM, sw schreibt in RAM).
WB (Writeback): Ergebnis wird zurück in das Register File geschrieben.

2. RAW Data Hazards (Read After Write)

Tritt auf, wenn ein nachfolgender Befehl ein Register lesen möchte, das von einem vorherigen Befehl noch nicht fertig zurückgeschrieben wurde.
Ohne Forwarding: Das Register File schreibt in WB (Stufe 5). Ein abhängiger Befehl in ID (Stufe 2) muss 2 Takte stallen (warten), wenn er direkt folgt!

3. Forwarding (Bypassing)

ALU → ALU: Das Ergebnis ist am Ende der EX-Stufe fertig! Die Forwarding Unit leitet den Wert direkt an den Eingang der ALU des nächsten Befehls weiter. 0 Stalls!
Load-Use Hazard: Bei lw sind die Daten erst am Ende von MEM da! Ein direkt folgender Befehl benötigt die Daten aber am Anfang von EX. Zurück in die Zeit reisen geht nicht $\implies$ 1 Stall ist unvermeidbar!

4. Die zwei Klausur-Geheimnisse der TU Darmstadt

1. Invertiertes Taktsignal am Register File: Schreiben erfolgt in der ersten Takthälfte, Lesen in der zweiten Takthälfte. Wenn Befehl 1 in WB ist und Befehl 4 in ID (Distanz 3), entsteht KEIN Hazard und 0 Stalls!
2. Das Register x0 (zero): x0 ist fest verdrahtet mit 0. Schreibt ein Befehl nach x0 (z.B. addi x0, a0, 5 in der Probeklausur), entsteht NIEMALS ein RAW Hazard!

5. Formel für Takte

$$\text{Takte} = N + (\text{Stufen} - 1) + \text{Stalls} + \text{Flushes} = N + 4 + \text{Stalls} + \text{Flushes}$$ Für Eintakt: $\text{Takte} = N \cdot 1$.
